## 二、一个请求的完整生命周期（结合本项目）

以访问 `http://127.0.0.1:8000/movie/detail/5` 为例：

```
浏览器请求
   │
   ▼
manage.py runserver 启动开发服务器（读取 mysite/settings.py）
   │
   ▼
mysite/urls.py（根路由）逐条匹配 urlpatterns
   │  匹配到 path('movie/', include('movie.urls'))
   ▼
movie/urls.py（应用路由）继续匹配
   │  匹配到 path('detail/<int:movie_id>', views.movie_detail, name='movie_detail')
   │  同时提取参数 movie_id = 5（int 转换器转换为整数）
   ▼
movie/views.py → movie_detail(request, movie_id=5)
   │  业务逻辑（本项目直接返回字符串）
   ▼
HttpResponse("你的电影id是:5")
   │
   ▼
返回给浏览器
```

**核心记忆点**：URL 匹配 → 提取参数 → 调用视图 → 返回响应对象。
`request` 是第一个固定参数（封装了本次请求的所有信息），URL 中提取的参数按位置依次传给视图。

## 三、核心知识点对照代码

### 3.1 manage.py 与启动入口

```python
# manage.py
def main():
    os.environ.setdefault('DJANGO_SETTINGS_MODULE', 'mysite.settings')  # 告诉 Django 去哪读配置
    from django.core.management import execute_from_command_line
    execute_from_command_line(sys.argv)   # 把 python manage.py xxx 交给 Django 处理
```

- `DJANGO_SETTINGS_MODULE` 指向 `mysite.settings`，这是整个项目的「配置来源」。
- `wsgi.py` / `asgi.py` 里也有同样的 `setdefault` 行，分别对应同步/异步部署入口。

常用命令：

```bash
python manage.py runserver            # 启动开发服务器
python manage.py startapp <名字>       # 创建应用
python manage.py makemigrations       # 生成迁移文件（模型 → 迁移脚本）
python manage.py migrate              # 执行迁移（迁移脚本 → 数据库表）
python manage.py createsuperuser      # 创建后台管理员
```

### 3.2 settings.py 关键配置

本项目基本保持默认，需要记住的几项：

| 配置项 | 本项目值 | 作用 |
|--------|---------|------|
| `INSTALLED_APPS` | 6 个 django 内置应用 | 注册应用；**自建应用也要加进来**才会被识别（Django 3+ 通常自动发现） |
| `ROOT_URLCONF` | `'mysite.urls'` | 指定根路由文件 |
| `DEBUG` | `True` | 开发模式，报错时显示详细页面；**生产必须 False** |
| `SECRET_KEY` | 一串密钥 | 签名用，生产应放环境变量 |
| `DATABASES` | SQLite3，`BASE_DIR / 'db.sqlite3'` | 数据库配置 |
| `MIDDLEWARE` | 7 个中间件 | 请求/响应的钩子处理（含 CSRF 防护） |
| `TEMPLATES` → `APP_DIRS` | `True` | 允许在「应用目录/templates/」下找模板 |
| `ALLOWED_HOSTS` | `[]` | DEBUG=True 时允许所有主机；上线需填写域名 |

### 3.3 全局路由 mysite/urls.py

```python
from django.contrib import admin
from django.http import HttpResponse
from django.urls import path, include, reverse
from book import views

def index(request):
    print(reverse("movie:movie_list"))      # 命名空间反向解析（打印到控制台）
    return HttpResponse("欢迎 来到 Django")

urlpatterns = [
    path('admin/', admin.site.urls),                                        # 后台
    path('book',  views.book_detail_query_string, name="book_detail_query_string"),
    path('book/slug/<slug:book_id>', views.book_detail_slug,  name='book_slug'),
    path('book/str/<str:book_id>',   views.book_detail_path,  name="book_str"),
    path('book/<int:book_id>',       views.book_detail_path,  name="book_int"),
    path('movie/', include("movie.urls")),                                  # 分发到应用
    path('', index, name='index'),                                          # 首页
]
```

**要点**

1. `path(route, view, name=None)` 三要素：路由规则、视图函数、路由名字。
2. `name` 是给 `reverse()` 用的「路由别名」——**反向解析不硬编码 URL**。
3. **匹配顺序自上而下，命中即止**：`'book'` 写在 `'book/<int:book_id>'` 前面，精确路径要放前面。
4. `include()` 的作用：把 `movie/` 之后的部分交给子路由继续匹配。

### 3.4 路径转换器

本项目一次性练习了主流转换器：

| 转换器 | 匹配规则 | 本项目路由 | 示例 |
|--------|---------|-----------|------|
| `str`（默认） | 非空字符串，不含 `/` | `book/str/<str:book_id>` | `/book/str/hello` |
| `int` | 整数 | `book/<int:book_id>` | `/book/123` |
| `slug` | 字母、数字、下划线、中划线 | `book/slug/<slug:book_id>` | `/book/slug/abc_123-def` |
| `uuid` | UUID 格式 | （代码注释中提到，未使用） | `/book/6f1c...-...` |
| `path` | 任意字符，**含 `/`** | （代码注释中提到，未使用） | `/book/a/b/c` |

- 转换器不仅**校验**格式（不匹配 → 404），还自动做**类型转换**：
  `<int:book_id>` 传到视图里是 `int`，`<str:book_id>` 是 `str`。
- 手动练习：访问 `/book/abc` 会 404（`<int>` 不接受字母），访问 `/book/str/abc` 正常。

### 3.5 查询字符串 Query String

```python
# book/views.py
def book_detail_query_string(request):
    book_id = request.GET.get("id")      # 读取 ?id=1 中的 id
    return HttpResponse(f"你要找的书的id是:{book_id}")
```

- 访问 `/book?id=1` → `book_id = '1'`（**始终是字符串**，需自行转换类型）。
- `request.GET` 是类字典对象，`.get(key)` 找不到返回 `None`（不会 KeyError，比 `[]` 安全）。
- 查询字符串**不参与路由匹配**，只在视图里通过 `request.GET` 读取。
- 两种传参方式对比：

| 方式 | URL 示例 | 视图接收 | 特点 |
|------|---------|---------|------|
| 查询字符串 | `/book?id=1` | `request.GET.get("id")` | 可选参数、分页/筛选常用 |
| 路径参数 | `/book/1` | `def view(request, book_id)` | 参数是路径一部分，必填、有类型校验 |

### 3.6 include 分发与应用命名空间

```python
# movie/urls.py
app_name = 'movie'          # ★ 应用命名空间

urlpatterns = [
    path('list', views.movie_list, name="movie_list"),
    path('detail/<int:movie_id>', views.movie_detail, name="movie_detail"),
]
```

- `include("movie.urls")` 把 `movie/` 前缀 + 子路由拼成完整路径：
  `movie/` + `list` → `/movie/list`
- `app_name = 'movie'` 声明**应用命名空间**，避免不同应用出现同名路由时冲突。
  访问时用 `命名空间:路由名` 的形式，如 `movie:movie_list`。

### 3.7 反向解析 reverse

`reverse()` = 根据**路由名**反推出 **URL**（正向：URL→视图；反向：视图→URL）。

代码注释中记录了三种实验：

```python
# 1. 基本用法：根据 name 反推 URL
reverse("book_detail_query_string")                    # → '/book'

# 2. 路径参数用 kwargs 传入
reverse("book_str", kwargs={"book_id": 1})             # → '/book/str/1'
# （若参数名为 book_id，也可用位置参数：reverse("book_str", args=[1])）

# 3. 查询字符串不参与 reverse，需要手工拼接
reverse("book_detail_query_string") + "?id=1"          # → '/book?id=1'

# 4. 带命名空间的路由：'命名空间:路由名'
reverse("movie:movie_list")                            # → '/movie/list'
```

**为什么要用 reverse**：URL 结构改动时只需改 `path()` 的写法，所有引用处自动生效，不用全局搜索替换字符串。

### 3.8 视图函数 FBV

```python
# movie/views.py
def movie_list(request):
    return HttpResponse(f"电影列表")

def movie_detail(request, movie_id):
    return HttpResponse(f"你的电影id是:{movie_id}")
```

FBV（Function-Based View）的约定：

1. 第一个参数必须是 `request`（`HttpRequest` 对象）。
2. 必须返回一个响应对象（`HttpResponse` / `JsonResponse` / `render(...)` 等），不能返回裸字符串。
3. URL 中的路径参数按**关键字参数**传入：`<int:movie_id>` → `movie_detail(request, movie_id=...)`。
4. 对应的另一种写法是 CBV（类视图），本项目尚未涉及。

## 五、易错点与注意事项

1. **路由末尾斜杠**：本项目用的是 `path('book', ...)`（无斜杠），访问 `/book` 可以，但访问 `/book/` 会 404。
   Django 官方惯例是**带尾斜杠**（如 `movie/`），`settings.APPEND_SLASH=True` 会自动给「缺斜杠」的请求补 `/` 重定向。
   后续项目建议统一写成 `path('book/', ...)`。

2. **路由顺序**：匹配自上而下。精确路径（`book`）要放在模式路径（`book/<int:book_id>`）之前，否则可能被抢先匹配。

3. **`request.GET.get()` 返回值类型**：永远是字符串（或 `None`），要参与计算需 `int(...)` 转换。

4. **f-string 误用**：`HttpResponse(f"电影列表")` 中没有占位符，`f` 前缀是多余的（无害，但可以去掉）。

5. **`reverse()` 的 name 冲突**：根路由与应用路由如果用同一个 `name`，反向解析会拿到第一个。用命名空间（`app_name`）解决。

6. **`DEBUG=True` 不能上线**：会暴露源码和设置；`SECRET_KEY` 同理不能提交到公开仓库。

7. **`include()` 的路径结尾**：`path('movie/', include(...))` 前缀建议以 `/` 结尾，子路由写相对路径（`'list'`），拼接才是 `/movie/list`。
